# RepoPact Workbench documentation

Workbench helps people inspect a governed repository and review supported
changes. RepoPact Core remains the authority for record meaning and validation.
Choose a guide by the task you need to complete.

## Use Workbench

- [User guide](user-guide.md) — open a repository, explore its records, review
  validation, and apply a supported plan.
- [Troubleshooting](troubleshooting.md) — recover from invalid repositories,
  stale plans, startup/build failures, and import problems.
- [GitHub snapshot import](guides/github-snapshot-import.md) — understand the
  optional exact-commit import flow, offline behavior, and its limitations.
- [GitHub App setup](guides/github-app-setup.md) — maintainer release
  configuration reference; not required for local Workbench use.

## Develop and extend Workbench

- [Contribution guide](../CONTRIBUTING.md) — ownership, development setup,
  validation, and pull requests.
- [Security policy](../SECURITY.md) — reporting and application trust
  boundaries.
- [Workbench agent contract](../AGENTS.md) — Core boundary, preservation, and
  platform-claim requirements.
- [Core contribution guide](https://github.com/ForgeWireLabs/repopact-core/blob/main/CONTRIBUTING.md)
  and [Core specification](https://github.com/ForgeWireLabs/repopact-core/blob/main/SPEC.md)
  — use these for Core-owned work and normative RepoPact semantics.

## See verified interfaces

The root [README](../README.md) describes the implemented workflow and links
screenshots to their provenance manifest and platform evidence. The [GitHub
guides](guides/) cover only the optional provider integration; local repository
use does not require a GitHub account or network connection.
